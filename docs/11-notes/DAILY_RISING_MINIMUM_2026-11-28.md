# Hundo Daily rising nomination minimum

Approved by Graem on 28 November 2026 after simulation review. The initial implementation and banner were verified locally and held. Graem subsequently authorized a paired production release and one explicitly named waiting-room opt-in; this note records the prepared candidate, not a completed deployment. Release receipts establish publication and hosted acceptance separately.

Newly created rooms use `biddingVersion: "minute-floor-v1"`. New player auctions require $1 during elapsed 0:00–0:59.999, $2 at 1:00, $3 at 2:00, and another dollar each minute. The backend transaction's server clock determines the accepted minimum. Client timestamps do not set it.

Each successful nomination persists its `minimumBid` and `nominatedAt`. That floor stays fixed throughout the player's auction, regardless of later room-clock changes. A player nominated for $1 at 0:50 can receive a $2 bid at 2:40. The initial bidder may offer more than the floor; this does not raise the floor for other bidders. Existing sealed-bid, earliest-tie, single-binding-bid and independent 120-second rules remain intact.

At the first accepted nomination, `biddingStartsAt` captures the room's auction-start anchor. Later NHL schedule corrections may still shorten deadlines under existing rules but do not reprice the bidding clock. Earlier waiting-room schedule corrections select the actual start normally.

Existing rooms with absent or unrecognized bidding versions keep classic $1 bidding, including waiting rooms. No global migration, backfill or read-side writes are added. Creation replay returns the original room and version. Existing rooms, bids, scores, notification settings and Leago rules are not upgraded by reads or startup. The sole separately authorized operator exception is waiting room “Saturdays slate” (`f7b27527-fa50-4580-923b-18d726e668a9`): after the compatible backend is deployed, exact room identity, waiting status, unchanged schedule and empty-auction guards must pass before enabling its bidding version. This preparation note does not claim that operation has occurred.

The $100 cap, seven positions and all outstanding-bid reservations remain unchanged. The existing reserve is still $1 for every other unfilled slot. This does not guarantee a complete roster as the minimum rises; no higher future-slot reserve, minimum ceiling or automatic filling was approved. Empty slots continue to score zero.

Additive room API fields are `biddingVersion`, `nominationMinimum` and `nominationMinimumIncreasesAt`; live auctions additionally expose `minimumBid`. Existing `rules.minBid` remains the base $1. The server rejects below-floor bids with `DAILY_BID_MINIMUM`. Identical accepted retries remain idempotent.

The player pool displays the current nomination minimum; live cards display the frozen player minimum. The blank bid form remains blank until typed, retains amounts across clock changes or errors, and never automatically raises or resubmits a bid. Existing room refresh-on-error behavior supplies fresh server state. Display interpolation uses the established server-adjusted clock; the backend remains authoritative. Older affordable auctions remain available when fresh nominations exceed a manager's cap. The creation preview and What is Hundo Daily instructions explain the rule and budget limitation.

## Auction-opening banner follow-up

Graem also approved an eye-catching eight-second opening banner explaining the minimum and cap bonus. `DailyAuctionOpeningBanner` replaces the existing cap-note row during each viewer's first visible live-room visit, including practice, spectators and late first visits. An icy blue/teal gradient, bright cyan edge and pale lettering distinguish it from Daily's purple; one brief sweep/pulse honors reduced motion. Its inline grid reserves the banner's height, so it neither overlays controls nor moves bid buttons when it expires; the original quiet cap note then returns.

The banner has three stacked rows with equal spacing: bold “Auction open”, the minimum rule, and the cap rule. Rising-room wording: “Opening bids start at $1 and rise $1 each minute. Players already up for auction keep their original minimum.” Bonus wording: “Every $1 of unused cap boosts your team’s positive FP by 0.25%.” The actual room bonus percentage is used; classic rooms and cap-bonus-off rooms receive matching copy instead. Paragraphs wrap naturally on narrow screens.

The eight-second window begins only when the room is in view and the tab is visible. Tab-local session storage remembers viewer, room and opening time; polls and refreshes do not restart the window. Refreshing during the window resumes its remaining time. Blocked storage falls back to memory. The notice is hidden outside the auction phase and never continues past the known auction deadline. No backend setting or room data is written.

Eleven focused banner tests cover exact expiry, StrictMode, polling, remounts, storage fallback, spectators, room/user separation, offscreen/hidden-tab gating, observer/timer cleanup and stale-phase deadline handling. All 121 combined Daily frontend tests across 21 files passed at the original held checkpoint, along with scoped lint, diff checks and the local build. Local Chromium desktop, portrait and landscape checks verify usable bid/chat controls, no focus capture, stable button positions, expiry, refresh deduplication, reduced motion and no horizontal overflow. The banner is included in the subsequently authorized paired release candidate; no hosted acceptance is implied by these local checks.
